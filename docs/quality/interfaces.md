# Quality telemetry and selection interface

Passive metrics are opt-in through `--quality-telemetry` or `--quality-selection`, translated to environment channel `racing_quality_telemetry=1`. Fixed mode emits an additional `RACING_QUALITY_EPISODE` marker only when enabled. Procedural terminal markers retain their existing schema with a nested `quality` record. Actor observations, rewards, actions, dynamics, sensor geometry and simulation cadence are unchanged.

`DrivingQuality` samples each completed physics interval once, inside `EvaluatePhysicsStep`, after the existing route projection and before any terminal/reset. It reads the Rigidbody velocity/rotation and existing lateral distance. It never advances progress or queries extra actor observations. Reset constructs fresh counters.

The `physics-quality-v1` record includes `ticks`, `offAsphaltTicks`, `offAsphaltFraction`, `maximumReverseSeconds`, `maximumStallSeconds`, `firstCornerPassed`, `firstCornerEntryDistance`, `firstCornerExitDistance`, `failureDistanceToFirstCorner` and `cleanFinish`. Off asphalt means lateral distance > roadWidth/2; the denominator includes every simulated interval. Reverse means signed body-forward velocity < −0.5m/s. Stall means velocity magnitude < 0.5m/s, excluding the first 2s launch grace only. Continuous spans reset when their condition clears. First-corner passage means projected travel reaches the exit of the first remaining sampled arc; entry/exit distances are relative to actual spawn. Failure distance is signed remaining distance to that entry at the terminal state. Fixed tracks currently report −1 corner-distance sentinels and no procedural corner claim.

Clean finish requires actual Finish termination, no reverse span >0.5s, no stall span >2s and off-asphalt fraction ≤5%. A 0.0001s accumulation tolerance distinguishes exactly 25/100 ticks from an extra tick. Actual tick counts and actual simulated seconds accompany decision-count estimated timings; they are different definitions.

`--quality-selection` requires procedural original-start evaluation (`track_eval_spawn_indices: [-1]`). Its measured rank is completion fraction, clean finish fraction, then actual mean finished simulated time only when every episode in the identical requested task set finishes. Partial successful subsets do not receive a timing tie-break. Suffix probes must be evaluated separately and cannot participate in quality selection. Historical fixed and procedural ranking defaults remain unchanged when this option is absent. Missing/version-mismatched/nonfinite/inconsistent quality ticks, asphalt fraction or terminal reasons abort selection. Measured completion must agree with the existing reward finish proxy.

Development configs own the eight original routes 20000–20007; no legacy 18-task suffix evaluation enters this gate. Pure geometry can be exported before any driving through `Racing.Editor.QualityGeometryExport.Run --racing-quality-geometry-output /absolute/ignored/runs/path.json`; it exports exactly those eight seeds with default generator parameters. Testing owns geometry-only capture-seed selection and all build/runtime evidence.

Python `--camera chase|overview` forwards `--portfolio-camera` to the presentation owner in view mode. Default remains chase. Presentation cameras do not influence environment data.

Bare `view` may resolve defaults only when the committed `configs/quality/accepted-view.json` exists and records `gate_passed: true`, repository-relative `checkpoint`, its exact `checkpoint_sha256`, `track_mode: procedural` and `track_seed: 1009`. The resolver verifies the actor file before use and selects seed1009 original start. No manifest is created by this implementation; the parent/testing owner writes it only after acceptance. Explicit checkpoint, track mode or config suppress this resolution entirely; explicit CLI flags retain argparse precedence. Training/evaluation historical defaults remain unchanged.

After parent acceptance of the quality gate, the native player defaults to procedural seed 1009 from the original start when no environment parameters supply a track mode or single-route seed. `--racing-manual` initializes the same route before enabling keyboard control; add `--racing-fixed` for the historical fixed-track manual game. This native flag changes only the fallback: an explicit environment-channel mode remains authoritative. Python always supplies its configured mode, so explicit fixed runs retain the fixed track. The scene has no embedded policy: a disconnected Agent-mode player idles with zero heuristic actions. Launch the accepted policy through Python `view`; manual mode does not run the accepted actor.

The accepted manifest's optional `quality_telemetry: true` enables passive metrics in the bare viewer. `--no-quality-telemetry` explicitly disables them, and `--quality-telemetry` enables them. Explicit checkpoint, mode or config continues to suppress all manifest defaults.

Pure helper boundary diagnostics: `Racing.Editor.DrivingQualityVerification.Run` checks 25/26 reverse ticks, 100/101 post-grace stall ticks, 100 launch-grace ticks, five/six off-asphalt ticks per 100, fresh reset counters and first-corner/nonfinish behavior. Player numerical parity with telemetry disabled/enabled remains testing-owned evidence.

`--stop-on-clean-development` is opt-in and requires quality selection. After a complete original-route evaluation measures both completion and clean-finish fractions of one, training writes `development-gate.pt`, records `outcome: development_gate_met` and closes through the normal latest-checkpoint/final-state cleanup. It sends no further training action or training reset after that evaluation. Defaults remain unchanged; this flag controls compute budgeting rather than environment behavior.
