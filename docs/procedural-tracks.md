# Seeded track layouts

Bare Python viewing selects the accepted procedural actor on seed 1009 from the original start. Explicit `--track-mode fixed` bypasses generation; the original loop, checkpoint, pose curriculum and selected weights remain available. Training and evaluation use their explicit configurations. No changes are made to vehicle dynamics, hitbox, road width, ray origin/directions/range, 15 observations, two actions, reward coefficients or 0.02s physics / five-tick decision cadence.

## Preserved open layout

`open-arcs-v1` uses a specified xorshift32 stream, straight segments and circular arcs. Alternating left/right arcs ensure both directions; straight length, arc angle and radius vary independently. Each route ends on a 20m straight. The same seed, parameters and generator version reproduce geometry independently of Unity's global random state. It is an open road with a single finish, not a lap. Seed range 0–16777215 permits exact environment-channel float encoding.

One sampled centerline drives the road and curb meshes, invisible nontrigger sensor MeshColliders on layer 8, crash MeshColliders on layer 0, spawn orientation, ordered gates and reward projection. Layer 8/9 collision remains ignored. Sensor ribbons follow the road edges at ±4.5m; crash ribbons follow the curb boundary at ±5.5m. Start/end crash caps close the outside world without blocking the finish. Presentation reuses existing materials; no new art pipeline or source scene regeneration is needed.

The original spawn is 4m along the route to clear the car's rear footprint from the start cap. Procedural training uses a separate deterministic spawn RNG keyed by spawn seed, track seed and episode sequence index: 75% of starts occur uniformly 10–20m before sampled turn entries, across left/right arcs and different positions/radii/angles; 25% use the original spawn. Turn-entry/exit distances, signed angles and radii are recorded. The finish is 6m before the end cap to allow the 5.4m car body to enter its forward-facing gate before hitting the cap. Credited progress begins at zero at the actual spawn. Pure generation metadata records road-plane spawn/finish positions; runtime metadata additionally records the exact elevated spawn pose/forward and elevated finish gate position/forward, absolute spawn/finish distances and remaining task distance `finishDistance-spawnDistance` (original start: `length-10m`). Intermediate gates are equally spaced in route distance at approximately 35m intervals, indexed 1 through N−1; index 0 finishes. Midroute starts set the first expected gate to the first intermediate gate more than 5m ahead of the pose, or directly to finish index 0 when no intermediate remains. Earlier gates remain geometrically present but cannot validate or earn rewards. Validated gate count and credited progress both reset to zero. The active ordered gate suffix, skipped count and spawn/task SHA256 are recorded. Gate tolerance remains 5m and forward-motion checks remain unchanged. Open projection intentionally replaces loop wrap semantics: it never wraps, credits a closing chord or accepts an out-of-order finish. Reward coefficients stay unchanged.

Validity constraints bound straights to 15–100m, radii to 18–80m, turn angles to 10–120°, sections to 2–12 and sampling spacing to 0.5–3m. Defaults are 5 sections, 25–55m straights, 22–42m radii, 25–100° arcs and 2m samples. Duplicate segments are rejected. Nonlocal segments must remain at least 15m apart; comparisons skip local bends whose along-route separation is under 30m. This provides clearance beyond both curb boundaries and prevents intersecting roads/nearby shortcut gates. Each open-layout seed has at most 64 deterministic candidate attempts; failure throws explicitly before replacing the active route. Generator v1 requires the baseline 9m road and 1m curbs.

Generated objects and colliders are disabled synchronously before replacing them; native meshes are released. Fixed-track objects remain preserved and reactivate when switching back. Route distance caches are rebuilt on every reset, including when consecutive seeds have equal sample counts. Procedural mode disables the fixed first-corner spawn curriculum.

## Configuration and provenance

Use `python/train_sac.py` with `--track-mode procedural`, `--track-train-seeds 101 211 307` and `--track-eval-seeds 1009 2003 3001`. `--track-seed` supplies a single-route fallback for evaluation. `--track-spawn-seed` sets the independent spawn stream; `--track-train-spawn-mode curriculum|original` controls training. `--track-eval-spawn-indices -1 0 1 2 3 4` explicitly evaluates original (-1) and all five turn-entry starts at `--track-eval-spawn-approach 15`. The default evaluation covers original plus every turn; use `--track-eval-spawn-indices -1` for a separate original-only procedural evaluation. Parameters have corresponding `--track-segments`, `--track-straight-min/max`, `--track-radius-min/max`, `--track-angle-min/max` and `--track-spacing` flags or JSON keys. Procedural training rejects overlapping train/evaluation seed sets. Configuration and checkpoint exports retain seed lists and parameters; resume rejects changes to these fields and to the spawn seed/modes/evaluation task schedule. Near-turn starts require a preceding straight at least approach+4m long; sampled training uses `straightMin >= spawnMax+4m`. NaN/infinite spawn inputs are rejected.

The environment parameter channel uses `racing_track_mode` (0=fixed, 1=procedural), `racing_track_seed_count`, `racing_track_seed_0...63`, and `racing_track_sequence_id`. A changed sequence ID resets the deterministic episode-boundary seed cycle; otherwise each reset advances one seed. No geometry changes during an active episode. Evaluations reset the sequence to the held-out seed × explicit spawn-index Cartesian product and run `eval_episodes` episodes per task. The channel additionally carries `racing_track_spawn_turn_i`, spawn mode (0 original / 1 sampled curriculum / 2 explicit turn), spawn seed, approach bounds, original fraction and fixed evaluation approach. Training restores its seed list after evaluation. Fixed approach probes retain their 10/15/20m poses.

Every procedural reset emits `RACING_TRACK: {JSON}` with generator version, effective seed, accepted attempt, parameters, realized geometry SHA256, spawn/task SHA256 and identity, centerline/edge/boundary coordinates, cumulative metres, gates, exact spawn/finish poses and task distance. The digest is SHA256 of version plus invariant round-trip X/Z centerline coordinates. Every terminal emits `RACING_EPISODE: {JSON}` with effective seed, sequence index, geometry digest, actual end reason/interruption, physics ticks, simulated seconds, travel metres, full route length and spawn-relative finish distance. The next automatically reset route may already appear in logs after the final evaluated episode; only completed terminal records count as outcomes.

`unity_env.track_records` parses these markers. Evaluation saves realized records alongside rollout arrays. Procedural policy selection prioritizes completion fraction across the same held-out route set, then mean clamped spawn-relative progress/task distance (actual Finish telemetry maps to one despite the car front reaching the trigger before its projected center reaches the gate), then decision-count time only when every seed episode finishes. Partial-completion timing does not break ties across different successful seed subsets. Fixed selection remains unchanged. Missing or misordered runtime telemetry aborts selection rather than guessing route identity. Procedural telemetry selection currently requires a built player and explicit log path; Editor connections are rejected.

## Verification handoff

Testing owns build/player execution. Run Unity batch entrypoint `Racing.Editor.ProceduralTrackVerification.Run` with `--racing-track-output /absolute/path/in/runs/geometry.json`. It checks deterministic generation/clearance for 1000 seeds and exports compact digests plus full geometry for train/held-out representatives. Representative edit-mode instantiated geometry checks cover sensor/boundary mesh vertices and ray hits, gate order, finish-before-cap, no endpoint wrap, reset state, jump rejection, equal-count cache invalidation, disabled old colliders and fixed mode restoration. They also verify all representative turn entries at 10/15/20m approach poses, zero skipped credit, first remaining gate validation and deterministic spawn task identity. For each training seed, 400 deterministic sampled starts verify every turn index plus original, left and right coverage; 10–20m approaches; and a near-turn fraction between 65% and 85% around the configured 75%. Compact counts are exported as `spawnCoverage`.

Build the existing scene with `Racing.Editor.PortfolioBuild.Build`; `RacingAgent` dynamically adds the generator on a procedural reset, so source scenes and their serialized baseline geometry remain untouched. Compare fixed full numerical rollouts before procedural smoke/training. Geometry checks do not establish policy generalization or training success; completed run evidence belongs in `docs/procedural-validation.md`.

A separate play-mode diagnostic entrypoint `Racing.Editor.ProceduralEpisodeVerification.Run --racing-episode-output /absolute/path/in/runs/episodes.txt` checks actual agent stepping on a midroute start: signed progress/time rewards, reset clearing held actions/steering/velocity, crash and 750-interval no-progress terminations, a temporary six-interval timeout interruption, and scripted physical suffix traversal with ordered finish and exact bonus. The diagnostic injects parameters through editor-only reflection into the installed ML-Agents channel. It restores temporary thresholds, saves no scene/asset changes and is not learned-policy evidence. Run it without `-quit`, as play mode executes asynchronously.

## Compact layout

The accepted viewer now uses `--track-layout compact` and seed 1009 from the original start. `compact-circuit-v1` creates open circuits with separate start and finish, alternating render-only red/white curbs and validated clearance. Each compact seed has at most 256 deterministic candidate attempts; invalid candidates are rejected before replacing the active route. Its compactness audit requires bounds aspect ratio ≤1.6 and maximum span / route length ≤0.40. Road width remains 9 m, curb width 1 m and minimum radius 22 m. The compact configuration uses five sections, 25–55 m straights, 22–42 m radii, 25–100° angle parameters and 2 m spacing; manifests record the effective realized route.

Explicit `--track-layout open` retains `open-arcs-v1` and its historical geometry hashes. Fixed mode remains explicit `--track-mode fixed`.
